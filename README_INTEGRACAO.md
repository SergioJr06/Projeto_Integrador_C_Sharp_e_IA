# SafeGuard IA — versão integrada para desenvolvimento

Este pacote mantém o motor de visão computacional e o backend existentes e acrescenta uma API de monitoramento, um dashboard Blazor e instruções de execução.

## Estrutura
- `SafeGuardBackend/`: API ASP.NET Core .NET 10, EF Core e PostgreSQL.
- `SafeGuardFrontend/`: dashboard Blazor Server com gráficos ApexCharts (carregados pelo CDN).
- `src/automacaototal.py`: motor YOLO existente, ajustado para enviar para a API na porta 5168.
- `models/best.pt`: modelo existente do repositório.
- `docker-compose.yml`: PostgreSQL local na porta 5433.

## Requisitos
- Visual Studio com workload ASP.NET e desenvolvimento Web e SDK .NET 10.
- Docker Desktop.
- Python 3.10+ recomendado para as dependências do motor de IA.
- Conexão com a internet para carregar ApexCharts e fontes durante o desenvolvimento.

## Início rápido (Windows)
- **`iniciar.bat`**: verifica Docker, .NET e Python; cria o ambiente Python na primeira vez; sobe o banco, a API (5168), o painel (5080) e, se você escolher, o motor de IA; e abre o navegador no painel. Requer o Docker Desktop já aberto.
- **`parar.bat`**: encerra as janelas e para o banco (os dados são mantidos).
- **Visual Studio Code:** abra esta pasta (a que contém `SafeGuardIA.sln`), instale as extensões recomendadas e use **Terminal > Executar tarefa > "Iniciar tudo (sem IA)"** ou **"Iniciar tudo (com IA)"**. Para depurar, use **Executar e Depurar > "API + Painel (depurar)"**. O motor de IA usa o ambiente `.venv`, que o `iniciar.bat` cria; se preferir, crie-o manualmente conforme a seção 4.

## Acesso pelo celular (mesma rede Wi-Fi)
1. Rode `liberar_celular.bat` **como administrador**, uma única vez (libera a porta 5080 no firewall para redes privadas).
2. Inicie o sistema com `iniciar.bat`; no final ele mostra os endereços, ex.: `http://192.168.0.15:5080`.
3. No celular, conectado ao mesmo Wi-Fi, abra esse endereço e entre com seu usuário e senha.

Se não abrir: confirme que o Wi-Fi do computador está como rede **Privada** no Windows, que o roteador não está com "isolamento de clientes"/rede de convidados, e que o IP usado é o do adaptador Wi-Fi/Ethernet (ignore IPs de Docker/WSL). Troque a senha padrão antes de expor o painel na rede. As fotos de evidência passam pelo painel e só aparecem para quem fez login.

## 1. Subir PostgreSQL
Na pasta raiz do repositório:
```bash
docker compose up -d
```
Credenciais locais: `localhost:5433`, banco `safeguard_db`, usuário `admin`, senha `senha123`.

## 2. Backend
No terminal, a partir da raiz:
```bash
dotnet restore SafeGuardBackend/SafeGuardBackend.csproj
dotnet run --project SafeGuardBackend/SafeGuardBackend.csproj --launch-profile http
```
API: `http://localhost:5168`. A especificação OpenAPI (JSON) fica em `http://localhost:5168/openapi/v1.json` (apenas em Development; não há interface Swagger UI). Para testar o POST, use `SafeGuardBackend/SafeGuardBackend.http` ou o motor Python.

> Use sempre o perfil `http`: o motor Python envia para `http://localhost:5168` e, em Development, o redirecionamento HTTPS fica desativado.

**Banco:** a entidade `Infracao` mapeia para a tabela `infracoes`. Em um volume PostgreSQL novo, o Docker executa automaticamente `database/init.sql`. Se o volume já existia antes dessa alteração, os scripts de inicialização não são executados novamente; nesse caso, rode o conteúdo de `database/init.sql` no banco.

```sql
CREATE TABLE IF NOT EXISTS infracoes (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  camera_id text NOT NULL,
  epis_faltantes text NOT NULL,
  nivel_confianca numeric NOT NULL,
  caminho_evidencia text NOT NULL,
  data_hora timestamp with time zone NOT NULL
);
```

## 3. Frontend
Em outro terminal:
```bash
dotnet restore SafeGuardFrontend/SafeGuardFrontend.csproj
dotnet run --project SafeGuardFrontend/SafeGuardFrontend.csproj --urls http://localhost:5080
```
Acesse `http://localhost:5080`. Você será levado à tela de login.

**Acesso inicial:** usuário `admin`, senha `SafeGuard@2026`. Troque antes de apresentar/publicar.

**O que o painel tem**
- Login com cookie de sessão (8 h) e botão **Sair**. Todas as páginas, exceto `/login`, exigem autenticação.
- Indicadores: infrações no período, ocorrências hoje, EPI mais recorrente e confiança média da IA.
- Gráficos ApexCharts: infrações por tipo de EPI (barras) e histórico de alertas por dia (área).
- Filtros por período (7 dias, 30 dias, todo o histórico) e por câmera; atualização automática a cada 60 s (o painel é composto de páginas simples, sem depender de conexão em tempo real).
- Tabela de histórico paginada, com miniatura e visualização ampliada da evidência.
- Exportação do histórico filtrado em CSV (compatível com Excel).
- Página **Câmeras e EPIs**: escolhe quais EPIs cada câmera fiscaliza, edita nome e fonte (webcam ou RTSP) e cadastra câmeras; salva automaticamente a cada mudança. Grava em `config/config.json` (caminho em `CamerasConfigPath`), que o motor de IA relê sozinho a cada ~1 s. Exige que painel e motor de IA rodem na mesma máquina/pasta do projeto.
- Quando a API não responde, o painel usa dados simulados e mostra um aviso na tela.

**Usuários e senhas** ficam em `SafeGuardFrontend/appsettings.json` (`Auth:Usuarios`), sempre como hash PBKDF2, nunca em texto. Para gerar o hash de uma nova senha:
```bash
python -c "import hashlib,os,base64,getpass; s=os.urandom(16); p=getpass.getpass().encode(); h=hashlib.pbkdf2_hmac('sha256',p,s,100000,32); print(f'pbkdf2\$100000\${base64.b64encode(s).decode()}\${base64.b64encode(h).decode()}')"
```
Cole o resultado em `SenhaHash`. Para adicionar mais usuários, repita o bloco no array. Em produção, prefira variáveis de ambiente (`Auth__Usuarios__0__SenhaHash`).

> O login protege o painel. A API (`/api/monitoramento` e `/evidencias`) continua aberta, como já descrito em "Limitações conhecidas".

## 4. Motor Python
```bash
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python src/automacaototal.py
```
Confirme que a câmera está configurada em `config/config.json` e que o modelo `models/best.pt` existe. O envio usa `http://localhost:5168/api/monitoramento`.

## Endpoints
- `POST /api/monitoramento`: `multipart/form-data` com `CameraId`, `EpisFaltantes`, `NivelConfianca` (0 a 1) e `Imagem` JPEG.
- `GET /api/monitoramento`: até 500 registros mais recentes.
- `GET /api/monitoramento/{id}`: detalhe de um registro.

As imagens são gravadas em `SafeGuardBackend/wwwroot/evidencias/`; somente o caminho relativo é salvo no PostgreSQL. Em produção, proteja evidências sensíveis por autorização e armazene fora da pasta pública.

## Limitações conhecidas
- **Credenciais:** `admin` / `senha123` estão em `appsettings.json` e `docker-compose.yml` apenas para desenvolvimento/trabalho acadêmico. Em produção, use variáveis de ambiente (ex.: `ConnectionStrings__DefaultConnection`) ou um gerenciador de segredos.
- **Sem autenticação:** os endpoints e as evidências (`wwwroot/evidencias/`) são públicos. Em produção, adicione autenticação e guarde as imagens fora da pasta pública.
- **Nomes dos EPIs:** o campo `EpisFaltantes` guarda os nomes das classes do modelo YOLO, em minúsculas e sem acento (ex.: `sem capacete`, `sem oculos`), separados por vírgula. O dashboard deve separar por vírgula e formatar o texto para exibição.

## Observações importantes
- A confiança do modelo é tratada como escala 0–1.
- O CORS permite origens locais usadas no desenvolvimento; ajuste para a origem real antes de publicar.
- O frontend usa dados fictícios quando a API está indisponível; esses dados não são infrações reais.
- Verifique a compatibilidade das versões do SDK, Docker e dependências no computador de execução. Não foi possível compilar/testar neste ambiente porque o SDK .NET não está instalado aqui.
